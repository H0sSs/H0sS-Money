# H0sS-Money

تطبيق عربي لتسجيل المصاريف بالصوت أو يدويًا، مبني باستخدام Expo SDK 54 وReact Native. المصاريف محفوظة محليًا في SQLite؛ لا يوجد backend خاص بالتطبيق.

## الوظائف

- تسجيل صوتي، تحويله لنص عبر Gemini أو OpenAI، ثم تحليل المصروف عبر Gemini أو OpenAI أو **Z.ai / GLM-5**.
- اختيار مستقل لمزوّد الصوت ومزوّد التحليل، مع تأكيد وتعديل البيانات قبل الحفظ.
- إضافة وتعديل وحذف المصاريف، البحث والفلترة حسب الفئة والتاريخ.
- ملخص اليوم وآخر 7 أيام، رسوم آخر 7/30 يوم، تفاصيل الأيام والفئات، ومقارنة شهرين تقويميين.
- هدف إنفاق وميزانيات فئات حسب **الشهر التقويمي**، وتنبيهات محلية عند 80% و100% والإنفاق المرتفع.
- تصدير CSV بالعربية، وتقرير PDF وصورة للإحصائيات.
- نسخ JSON محلية أو على Google Drive **يدويًا فقط**، مع الدمج أو الاستبدال.
- قفل بالبصمة/رمز الجهاز، وإعادة القفل بعد 15 ثانية في الخلفية.
- ثيم فاتح وداكن، شعار مخصص محفوظ داخل النسخة الاحتياطية، وملخص مسموع.

## الذكاء الاصطناعي والخصوصية

المفاتيح تدخل من الإدارة وتُحفظ في SecureStore، ولا تُضمّن في APK أو Git. رموز Google Drive تحفظ أيضًا في SecureStore ويتم ترحيل الرموز القديمة من SQLite تلقائيًا.

التسجيل والنص يرسلان مباشرة إلى المزوّد الذي تختاره؛ لذلك التحليل الصوتي يحتاج إنترنت ومفتاح API صالحًا ورصيدًا/حصة متاحة. عرض البيانات والإدخال اليدوي والحسابات لا تحتاج سيرفر. تغيير العملة يغيّر وحدة العرض فقط ولا يحوّل أسعارًا أو عملات.

### إعداد Z.ai / GLM-5

1. افتح https://z.ai/manage-apikey/apikey-list وسجّل الدخول.
2. أنشئ API Key لخدمة Model API وتأكد من توفر الوصول إلى `glm-5` والرصيد حسب حسابك. لا تعتمد على اشتراك أدوات البرمجة كبديل غير متحقق لخدمة تطبيقك.
3. في الإدارة ← الذكاء الاصطناعي: أدخل المفتاح في Z.ai ثم اختبر الاتصال واحفظه.
4. اختر Z.ai لتحليل المصروف. لتحويل الصوت اختر Gemini أو OpenAI وأدخل مفتاحه أيضًا، لأن GLM-5 يقبل النص فقط.

المراجع: https://docs.z.ai/guides/llm/glm-5 و https://docs.z.ai/guides/overview/quick-start

### Google Drive

على Android يستخدم Google Sign-In الأصلي بدل عناوين الرجوع المخصصة. أنشئ Web OAuth Client ID وأدخله في التطبيق، وأنشئ Android OAuth Client بنفس مشروع Google Cloud باسم الحزمة `com.hossmoney.app` وبصمة SHA-1 من ملف signature.txt المرفق بالبناء. فعّل Drive API وأضف حسابك لمستخدمي الاختبار إذا شاشة الموافقة غير منشورة. يلزم وجود Google Play Services. نجاح الربط الفعلي يعتمد على إعداد Google Cloud ونشر شاشة الموافقة وحساب الاختبار. نطاق الوصول `drive.file`، ويُنشأ مجلد `H0sS-Money-Backups`. الاسترجاع يتطلب الاتصال بالحساب الذي أنشأ النسخة.

## البيانات والاسترجاع

SQLite مباشر عبر `expo-sqlite`، بدون Drizzle. الجداول: categories، expenses، settings، notification_log. الإصدار 2 يضيف معرفًا دائمًا لكل مصروف وفهارس؛ الترحيل يحافظ على البيانات القديمة.

استيراد v1 وv2 يتحقق من السجلات قبل الكتابة ثم يستخدم معاملة واحدة. الدمج يعيد ربط الفئات ويحافظ على معرفات المصاريف بدل استخدام الأرقام المحلية المتعارضة. المفاتيح ورموز OAuth لا تُصدّر. سجل الإشعارات ليس جزءًا من النسخ.

## التطوير والفحوص

```sh
npm ci --legacy-peer-deps
npm run check
npx expo-doctor
npm start
```

اختبارات Node 24 تستخدم SQLite فعلية لاختبار الترحيل وحساب الشهر والدمج وعدم التكرار والرجوع عند الفشل. تستبدل واجهات Expo الأصلية فقط أثناء اختبار الخدمات؛ لا تعوّض اختبار جهاز Android.

## بناء APK

GitHub Actions يشغّل فحوص الكود ثم يبني `assembleRelease` مع R8 وتقليل الموارد:

- **arm64**: للأجهزة التي تدعم arm64-v8a، أصغر حجمًا.
- **universal**: يشمل armeabi-v7a وarm64-v8a وx86 وx86_64.

ملفات المراجعة متاحة في Actions Artifacts، ولا تُنشر تلقائيًا كإصدار عام. بعد البناء يُفحص التوقيع وعدم وجود `debuggable`، ثم اختبار بدء التشغيل على محاكي Android 35.

**التوقيع:** إصدار المراجعة يستخدم شهادة تطوير Expo المرفقة بقالب المشروع. تحسين Release لا يجعل شهادة التطوير شهادة إنتاج. يلزم keystore خاص ثابت للنشر طويل الأمد؛ لا تنشر مفتاح توقيع خاص في Git. التحديث فوق APK سابق يتطلب تطابق الشهادة؛ صدّر بياناتك قبل أي إزالة للتطبيق.

## خريطة المشروع

- `app/(tabs)`: الرئيسية والإحصائيات والمصاريف والإدارة.
- `app/_layout.tsx`: التهيئة والقفل ومراقبة دورة حياة التطبيق.
- `lib/db.ts`: التهيئة والترحيل والفهارس.
- `lib/services.ts`: CRUD والحسابات والاستيراد والتصدير.
- `lib/dates.ts`, `lib/validation.ts`: التواريخ والتحقق وتصدير النصوص بأمان.
- `lib/ai.ts`: مزوّدو الصوت والتحليل.
- `lib/drive.ts`: OAuth والنسخ اليدوية.
- `lib/notifications.ts`: تنبيهات محلية وسجلها.
- `components/AISettings.tsx`, `components/PageHeader.tsx`: إعداد المزوّدين وتصميم موحد.

## حدود الاختبار

البصمة والميكروفون وGoogle OAuth ومزوّدو API يلزم اختبارهم على هاتف بمفاتيح المستخدم. نجاح الفحوص والبناء لا يضمن غياب كل الأخطاء على جميع الأجهزة.
